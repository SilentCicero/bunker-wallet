# Experimental browser PQ wallets

## Status and scope

User-authorized **trusted-client experimental registration**, Sepolia test ETH only. This is not audited security, mainnet support, trustless KeyGen provenance, NIST certification, or a security ranking between the UI names. An isolated [test preview](https://bunker-wallet-pq-sepolia-test.pages.dev) is live. Its V3 shared factory is [`0x85e66387d341aa1e03f9165cfd2013340a738a45`](https://sepolia.etherscan.io/address/0x85e66387d341aa1e03f9165cfd2013340a738a45), deployed in block 11912805 and verified through a second RPC. Fresh Standard wallets deploy a V3 guard; fresh C10/ML-DSA wallets use that V3 shared factory. **No public V3 Safe has been created or funded in the hosted UI.** Independent security review was explicitly deferred for this testnet-only release; each user chooses whether to fund a new disposable Safe.

Standard wallets and derivation stay unchanged. The chain31337 research kernel is unchanged. A separate `packages/contracts-experimental` namespace pins chain11155111 and message domain `BUNKER_EXPERIMENTAL_PQ_V1`. Browser creation, funding, ETH send+EC rotation, repeated EC-sequence renewal, phrase recovery and encrypted-browser-vault restore are implemented. The PQ owner stays fixed. The V3 guards allow 1–8 bounded external `CALL`s (up to 8192 calldata bytes each) only before an exact atomic next-owner funding/swap suffix; inner delegatecall, privileged Safe administration, modules, guard changes and arbitrary self-calls remain blocked. Both PQ signatures are still required. This is a **contract capability for external Safe clients**, not a frontend feature: this UI sends ETH only. Standard V3 still stops after 19 rotations; PQ V3 retains its final-key renewal. Hardware/offline signing, arbitrary PQ-key import, PQ-key rotation UI, and mainnet are not provided. Existing V1/V2 Safes do not acquire V3 privileges and cannot be silently upgraded.

## Keys and recovery

- Generate a standard24-word BIP-39 phrase (256bits of entropy). Empty BIP-39 passphrase, as in the existing wallet.
- PQ derivation uses the64-byte BIP-39 seed directly, **not a BIP32/secp256k1 private scalar**. HKDF-SHA512 salt is `BUNKER_C10_FIPS_V1` or `BUNKER_MLDSA44_V1`; info is big-endian `account:u32 || index:u32 || epoch:u32`. Current UI fixes all three to zero and records version1 metadata.
- C10:48 HKDF bytes split into16-byte public seed and32-byte secret seed; the dedicated C10-FIPS signer computes the16-byte root. Signatures are4008bytes. This is custom C10, not SLH-DSA. The fixed key has a finite, parameter-specific signature budget, shared across devices/Safes using the same phrase/domain. There is no global usage counter: do not reuse its phrase across wallets or assume unlimited signing.
- ML-DSA-44:32 HKDF bytes go through real standard KeyGen; public key1312bytes, pure/empty-context signature2420bytes. The browser prepares the complete20545-byte blob and compares **every deployed byte** to its own regenerated blob before funding or signing and during recovery.
- EC cycle0 preserves `m/44'/60'/7331'/0/i`. At reserved index19, both owners authorize funding index20, swapping to it and committing the next sequence. Later cycle `c>=1` commits20 keys at `m/44'/60'/7331'/3'/c'/(i-1)'` for `i=1..20`. Cycle-start owner is the prior cycle's reserved key. The guard increments an authoritative on-chain `sequenceEpoch`; recovery verifies current owner and all remaining commitments. Cached metadata never overrides chain state. The browser rejects unsupported cycle/index ranges rather than falling back to EC-only.

Use a new test-only phrase; never import one securing real funds. Keep the phrase, signing mode and Safe address offline. Creation now uses the same selection → 24-word backup → recovery check (or explicit skip) → optional browser password → setup-funding → Safe-creation screens for Standard, C10 and ML-DSA. New PQ setups require a browser password before persisting their public checkpoint; the phrase is saved only in the encrypted experimental vault. Older checkpoint-only setups cannot regain an absent phrase and require the original phrase and Safe address. A matching encrypted vault supports browser restore. Standard's device-key-backed no-password session is unchanged. Mode, PQ derivation version/account/index/epoch, public key and EC-sequence version are authenticated in encrypted-vault metadata. Deployment checkpoints contain no private key or mnemonic. Fresh-browser phrase+Safe-address recovery does not require those checkpoints. A phrase alone cannot discover an unknown Safe address. Clearing storage during an unfinished deployment can orphan already paid-for components; keep the saved record/transaction hashes. Explicit recovery requires the existing Safe address; unlock of a matching saved vault and resume of a retained partial deployment checkpoint are separate local flows. This preview preserves one experimental wallet checkpoint per browser origin. In Create, **Replace saved test wallet** allows deliberate deletion of an intact, non-pending PQ browser checkpoint and vault after explicit acknowledgement; it never deletes the on-chain Safe or moves funds, and old access still needs the original phrase and Safe address. A pending/uncertain signed intent, malformed checkpoint, missing checkpoint with vault, or uncertain Standard deployment blocks replacement and retains all data. Unfinished non-pending deployments can be abandoned, losing the saved component addresses. A separate browser profile remains an alternative.

One phrase supplies algorithmic diversity, **not independent authentication factors**. Browser-origin compromise, extensions or loss of the phrase can compromise both owners. JS cannot guarantee physical erasure of all secret copies; worker termination, buffer wiping and clearing references are best-effort lifetime controls.

## What registration establishes—and does not

The experimental ML-DSA adapter checks exact public-key length, canonical10-bit decoding, the upstream centered-lift degeneracy floor (at least512 of1024 coefficients larger than gamma2 in absolute centered lift), canonical raw-key hash identity separate from blob hash, blob length/hash and the fixed Keccak-helper hash. The known all-zero and all1023 coefficient keys are rejected. These checks are **not a complete nondegeneracy or genuine KeyGen proof**, and they do not compute the complete `prepare(pk)` relation on-chain.

The trusted browser must generate/rederive the key itself and compare the exact public key, blob, immutable-patched adapter/factory/guard/setup/verifier runtimes, official Safe dependencies and ownership policy before use. No arbitrary PQ-key import is supported. Factory dependencies are immutable codehash pins supplied at deployment; the browser establishes that they are the pinned real implementations, not arbitrary contracts with matching caller-supplied hashes. Current helper/blob/verifier integrity is checked again on use. A prepared adapter grants no authority; Safe authorization still needs both current owners.

## Transaction safety and gas

The broadcaster is a separate EOA, not an extra Safe owner. The UI shows broadcaster and Safe balances/addresses separately. Each action is RPC-estimated, compared to current block capacity, given a10% margin, and checked against the broadcaster's balance at explicit fee caps. The guard's0.001 test ETH next-owner funding is **not guaranteed to cover the next fee**; top up the displayed broadcaster if required.

Sepolia's2026 Glamsterdam gas model charges separate state gas. Do not treat an estimated total above16.7M as an automatic rejection or extrapolate Osaka Anvil fixture gas to current Sepolia fees. Read-only estimates and two funded headless Sepolia runs are recorded below; these single-run fees are not a fee/cost guarantee.

Signing is fenced after async request preparation and after local signing. Before broadcast, the wallet authenticates/encrypts the exact signed transaction and chain/sender/nonce/target/value/calldata/gas/fee intent under AES-GCM. The key is derived from the phrase using a separate `BUNKER_TX_OUTBOX_V1` HKDF domain and held as a nonextractable in-memory CryptoKey. Only hash, kind and ciphertext persist; never plaintext signed bytes, keys or phrase. Persistence failure prevents dispatch. RPC response loss retains unknown outcome and blocks new actions. Recovery reconciles the original hash; an explicit retry decrypts and validates the outbox and broadcasts **identical bytes**, never a replacement payment. Lock does not revoke an already signed/broadcast transaction. Attestation snapshots one explicit block and uses the authenticated receipt height after a mined operation; public RPC backends briefly behind that block may require waiting before read-only reconciliation. If a send hash is confirmed on-chain but a `Policy()` read error leaves a pending outbox in the browser, do not rebroadcast or delete the checkpoint: use the balance/status check to reconcile the original receipt, or unlock via the saved vault / recover with the original phrase and Safe address after refreshing. If a transaction is replaced externally or receipts remain unavailable, the client fails closed and manual reconciliation may be required.

Partial deployment checkpoints resume completed components. A pending broadcast must be reconciled/rebroadcast before further setup. Multiple tabs use an exclusive Web Lock and storage-change invalidation. Lock/cancel terminates the signer worker; failed initialization/dispatch also destroys the signer instead of retaining an old identity.

## Reproducible build and checks

Pinned sources/licenses and build settings are in `packages/pq/README.md`. Build artifacts are isolated from Standard solc0.8.24 output:

```sh
bun install --frozen-lockfile
bun run pq:build
bun test
bun run typecheck
bun run build
(cd packages/contracts && forge test)
(cd packages/contracts-experimental && forge test)
(cd packages/pq/c10 && cargo test --release --locked)
```

The runner seeds it with the actual official Sepolia Safe1.4.1/factory/MultiSend runtimes recorded in `tests/fixtures/sepolia-safe-1.4.1.json`. ## Preview gates

On the dedicated test preview, choose **Create wallet (Testnet)**. Move the three-stop security slider to Standard, Quantum Shield or Maximum; each position shows its key combination and historical gas observation, with expandable limits and standard/design links. Choose **Create wallet** for the same phrase, check, password, fund-setup-key and Create Safe wallet milestones in every mode. On normal completion, all three attest and fund the new Safe; shared V3 PQ creation funds the Safe with 0.01 test ETH by default and retains remaining setup-key funds for gas. The original signed creation/funding intent must be reconciled after an uncertain outcome, never replaced with a new Safe. The selector names signing combinations, not a proven security ranking. **Recover wallet** is a separate header route, never beside Create: enter the existing Safe address and 24-word phrase. Read-only Safe ownership/threshold, bound PQ-owner algorithm and guard data route to Standard, C10 or ML-DSA; only full subsequent owner/key/verifier/guard/sequence attestation unlocks the wallet. A missing Safe cannot be recovered or used to create a new one from this route. **Unlock** is separate for a matching saved browser vault; **Resume interrupted setup** is available only with the original public pre-Safe checkpoint. A PQ vault without its checkpoint fails closed rather than risking creation of another Safe. The experimental preview similarly binds unfinished Standard setup to a nonsecret versioned setup-address journal. `ready` permits matching vault/session resume; a passwordless, unfinished Standard setup can also use the separate **Resume unfinished setup** action with its original phrase and matching local ready journal after Lock. This is not existing-Safe recovery. `deploying` is written before deployment broadcast and records the factory hash when known. An unknown deployment or missing journal fails closed—never create a replacement Safe; inspect the original setup key’s transactions and recover with the Safe address. The journal is cleared only after the Safe address is persisted. If a created Safe's checkpoint was lost, recover it with the phrase and Safe address. Local Anvil hashes are not linked to public Sepolia Etherscan. Example gas figures are observations from one Sepolia run, not fee guarantees or a proven security ranking.

Default builds keep PQ disabled. Only localhost/127.0.0.1 and the exact `bunker-wallet-pq-sepolia-test.pages.dev` hostname can enable `VITE_EXPERIMENTAL_PQ=1`. The live V3 preview was built with `VITE_EXPERIMENTAL_PQ=1` and the exact-host gate; `VITE_BROWSER_SEPOLIA_E2E=1` is a **local browser-test flag**, not present in that production build. The isolated preview pins V3 for fresh PQ creation and retains the V2 pin for legacy recovery and pending `createV2` reconciliation. No production allowlist was broadened. Experimental RPC defaults to that public endpoint. The preview's assets and read-only UI were checked in a hosted browser. Earlier V1/V2 funded lifecycles ran headlessly on public Sepolia; the V3 funded lifecycle and four-rotation browser checks have run only on disposable Anvil, not through the hosted UI. Do not deploy a build carrying a local Anvil RPC override.
