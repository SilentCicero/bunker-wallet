# Contract test matrix (Sepolia-only, unaudited)

Run each Foundry project separately; a passing test suite is not an audit or a proof that an exploit is impossible. The Safe 1.4.1 contracts under `packages/contracts/lib` are **vendored third-party code**, not Bunker-authored contracts. They are exercised by proxy integration tests, not re-audited here.

| Source | Positive path | Negative/adversarial path |
| --- | --- | --- |
| `packages/contracts/src/BunkerRotationGuard.sol`, `BunkerSafeSetup.sol` | `BunkerSafeIntegration.t.sol`: atomic setup, ETH send, funding, owner rotation | Wrong future owner, missing/wrong funding, reverted recipient rollback, index exhaustion, wrong MultiSend hash |
| `packages/contracts/src/BunkerRotationGuardV3.sol` | `BunkerSafeV3.t.sol`: setup, calldata calls, eight-CALL boundary, rotation | Malformed batch and overflowed ABI length, zero/nine CALLs, invalid signatures/replay, privileged targets/delegatecall, funding mismatch, rollback, 19-rotation exhaustion, fuzzed lengths/count/funding |
| `packages/contracts/src/BunkerHybridFactory.sol`, `HybridSafeOwner.sol`, `BunkerHybridRotationGuard.sol` | `BunkerHybridIntegration.t.sol`: ECDSA+C10/ML-DSA paired ownership, factory setup, renewal, replacement | Malformed signature and key framing, incorrect signer/order, forbidden Safe mutations, rogue module, changed dependency/storage, wrong chain, replay, rollback/reentrancy |
| `packages/contracts-experimental/src/ExperimentalFactory.sol`, `ExperimentalOwner.sol`, `ExperimentalRotationGuard.sol` | `LegacyFactory.t.sol`: C10/ML-DSA creation and candidate registration; `ChainBoundary.t.sol` | Wrong caller, forged guard initialization, duplicate owner, invalid key/preimage/signature length, changed verifier, wrong chain, candidate without joint owner installation |

| `packages/pq/verifiers/mldsa/src/{MLDSA44Verifier,Decode,FastKeccak170,Ntt,InvNtt,IMLDSAVerifier}.sol` | `MLDSAVerifier.t.sol`: real public ML-DSA-44 signature and prepared blob; helper libraries exercised through verifier | Changed message/signature/blob, wrong helper at construction or runtime, fuzzed lengths |

The verifier vectors are **public disposable fixtures**. C10 uses the pinned `0x01` seed and `0x02` message. ML-DSA uses zero-filled KeyGen seed, a 32-byte `0x02` message and a hedged (non-deterministic) signature; `mldsa-public-test.blob` is the existing pinned public-side prepare routine's output and its Keccak-256 is `0xeab86422c3acade3a03a9f0aa4fb16b4f5806d99102eb8316ceddb444675a3bf`. Never use either fixture as a real wallet key.

Remaining limits: factory/guard tests use mock PQ verifiers for policy isolation; real verifier vectors and Anvil/browser lifecycle cover cryptographic interoperability separately. The verifier cannot prove honest browser KeyGen or prepared-blob provenance. No exhaustive state-space proof, complete fuzz corpus, independent security review, or mainnet authorization is claimed. On-chain Safe signature authorization occurs before the guard; guard checks supplement, not replace, Safe's 2-of-2 verification.
